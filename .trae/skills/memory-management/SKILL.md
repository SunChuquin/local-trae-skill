# 主动保存 TRAE 对话到记忆

在 TRAE 对话中，把值得沉淀的问答**主动**存入本地向量记忆库，供后续任意对话（前端 / TRAE）自动检索命中并回顾。用户无需每次说"记住"，由本 skill 自行判断价值并保存。

## 前置条件

后端服务必须在运行（`http://127.0.0.1:8000`）。如果请求失败，提示用户启动后端：`.\启动后端.bat`

## 保存接口

**POST** `http://127.0.0.1:8000/api/memory/save`
```json
{"question": "用户当前的提问", "answer": "要记住的回答/结论", "source_note": "可选来源备注"}
```
返回 `data.saved=true` 表示成功。

## 主动保存规范

1. **静默调用**：直接发请求保存，**不要**向用户提及 API、HTTP、状态码等概念
2. **主动触发**：每完成一次知识性问答，主动判断本次问答**是否有长期复用价值**，有则**自动**调用保存接口，无需用户说"记住"。保存后仅在回答末尾轻描淡写一句"（已存入记忆）"，不打断阅读
3. **值得保存**（自动存）：
   - 规范外经验 / 踩坑教训（如"某库 Python 3.8 会报 X 错，需用 3.10"）
   - 验证过的明确结论（如"ATR 字符间隔最大 9600 etu"）
   - 技术方案要点、配置规则、参数取值
   - 针对本项目的决策与约定
4. **不值得保存**（不存）：寒暄问候、临时性内容、与项目无关的闲聊、纯机械性操作
5. **去重**：同一问题若已在记忆中存在，不重复保存
6. **查看/删除/统计**：若用户想看/删/数记忆，**引导其到前端网页的「记忆管理」页**（侧边栏），不在本 skill 内调用列表/删除/计数接口

## 示例

用户："为什么 python clean_kb.py 报 int | None 错误？"
→ 回答后主动保存 `{question:"clean_kb.py 报 unsupported operand type for | 的原因", answer:"int | None 是 3.10+ 语法，需用 .venv310 的 python 运行，全局 3.8 不行"}`，回复末尾"（已存入记忆）"

用户："早上好"
→ 不保存，正常寒暄
