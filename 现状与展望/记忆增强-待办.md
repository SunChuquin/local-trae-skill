# 持久化记忆增强 — 待办清单

> 目标：让本项目的 RAG 从"无状态、用完即弃"走向"记住成功交互"。后续会话可依据本文件继续展开实现。

## 已完成（后端 MVP，可运行）

- 新增 [memory_service.py](backend/app/services/memory_service.py)：问答记忆层
  - 独立向量集合 `mem_qa` 存"问题 → 已验证答案"，metadata 带 answer/时间
  - `save_qa(question, answer, source_note)` 保存；`search(query)` 按语义命中；`count()` 统计
- 改造 [rag_service.py](backend/app/services/rag_service.py)：`retrieve()` 检索前先查记忆，高相似度命中直接返回缓存答案；全库检索排除 `mem_` 前缀内部集合
- 新增 [memory.py](backend/app/routers/memory.py) 路由（已注册到 main.py）
- 已验证闭环：保存问答 → 近似问法命中（相似度 >0.9）→ 直接返回缓存答案；普通文档检索不受记忆污染

## API 参考（MVP）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/memory/save` | 保存问答 `{question, answer, source_note?}` |
| GET/POST | `/api/memory/search` | 检索记忆 `query, top_k, threshold?` |
| GET | `/api/memory/count` | 记忆条数 |

## 待办（后续实现）

### P0 — 前端接入（让用户能真正"记住"）
- [ ] 前端对话组件加"记住这次回答"按钮 → 调 `POST /api/memory/save`（question=用户提问, answer=助手回答）
- [ ] 命中记忆时在回答中标注"（来自问答记忆）"，与文档检索结果区分
- [ ] 前端加"记忆管理"页：查看/删除已存记忆（需后端补 `GET /api/memory/list`、`DELETE /api/memory/{id}`）

### P1 — 自动学习（参考 ERM 思路）
- [ ] 用户对回答点赞/采纳后，自动调用 save 入库（无需手动）
- [ ] 可选：结合 `use_skill` 对话流程，每次成功问答自动沉淀记忆
- [ ] 记忆去重：同一问题已存过则更新答案而非重复插入（现用 sha1 固定 id，可改为 upsert 覆盖）

### P2 — 记忆管理健壮性
- [ ] 记忆条数上限 / 过期衰减（旧记忆降权或淘汰，避免无限膨胀）
- [ ] 记忆命中阈值可配置（现默认 0.85，可在 skill_config 或 memory API 暴露）
- [ ] `mem_qa` 集合的备份/清理纳入 clean_kb 或独立维护（注意：clean_kb.py 会清空所有 chroma 集合，需确认是否也清记忆，或单独处理）

### P3 — 检索优化
- [x] 记忆命中分级（已完成）：一字不差（exact）直接返回缓存答案；近似命中不短路，作为"问答记忆（参考）"附带回文档检索结果，交由上层 Agent 判断是否真是用户所问
- [ ] 前端对话结合该参考上下文，向用户确认"是否正是您想问的/是否采用该记忆答案"

## 验收标准（建议）
- 前端点击"记住"后，另起会话问相似问题，能直接得到之前保存的答案
- 命中记忆的回答在 UI 上有明确标识
- 不影响原有文档检索准确性（记忆集合不混入普通检索结果）
